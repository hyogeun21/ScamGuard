- 말풍선/질문 목록/행동 체크박스는 CSS/HTML로 그리므로 별도 이미지 불필요.

컴퓨터 조사 수정 안내

화면 연결

| 시나리오      | 연결                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| 1 채용        | 첫 화면 4개 → 각 내용 → 첫 화면                                               |
| 2 재택부업    | 일반 3개 → 내용 / 업무 사이트 → 업무 목록 → 업무 내용                         |
| 3 투자 리딩방 | 금융회사/등록조회 → 내용 / 투자앱 → 항목 → 가상출금 결과 / 공식앱 정보 → 항목 |
| 4 숙소예약    | 일반 2개 → 내용 / 검색 → 검색결과 → 예약문의 / 예약·결제 → 결제안내확인       |

컴퓨터창은 X 또는 ESC로 전체 닫습니다. 뒤로가기는 기획에 지정된 이전 화면으로 이동합니다.
숙소예약의 예약 및 결제안내창은 뒤로가기 없이 결제안내확인 버튼만 있습니다.
가상출금요청은 승인/거부 결과와 이유를 표시합니다. 현재 거부 예시이며 예/아니오 선택창이나 실제 거래 기능이 아닙니다.

수정 파일

src/game/computerContent.js의 COMPUTER_SCENARIOS를 수정합니다.
1=채용, 2=재택부업, 3=투자 리딩방, 4=숙소예약입니다.

각 시나리오는 root(시작 화면 ID)와 nodes(화면 데이터)를 가집니다.
각 화면에는 다음 데이터가 있습니다.

{
  title: '화면 제목',
  body: '본문\n\n여러 줄도 가능',
  backTo: '이전화면ID', // null이면 뒤로가기 없음
  actions: [
    { label: '선택지 문구', target: '이동할화면ID' },
    // 아래 형태는 본문 목록 대신 하단 이미지 버튼으로 표시합니다.
    { label: '예약문의', target: 'inquiry', buttonKey: 'computerInquiry' }
  ]
}

모든 target/backTo는 같은 시나리오 nodes 안의 ID와 일치해야 합니다. npm test로 검사할 수 있습니다.
업무 개수는 tasks.actions에 추가하고 그 target에 해당하는 업무 페이지를 nodes에 추가하면 늘어납니다.
업무의 backTo는 tasks로 지정합니다.

콘텐츠 상태

구체적인 제목을 제공하지 않은 일반 선택지와 모든 본문은 교체용 예시입니다.
레이아웃과 화면 연결을 먼저 구현한 상태이며 실제 교육용 문구를 확정한 것은 아닙니다.
외부 웹사이트, 실제 금융조회/숙소 검색/예약/출금은 연결하지 않습니다. 모두 게임 내부 모의 화면입니다.

코드 구조

OverlayScene.renderComputer가 현재 페이지를 읽고 공통 UI를 만듭니다.
가변 텍스트 높이, 내부 스크롤, 포커스/키보드 잠금은 기존 조사창과 같습니다.
computerPages는 방문한 페이지 ID를 중복 없이 보관하고 새 게임 시작 시 초기화됩니다.
화면을 닫고 다시 열면 시작 화면으로 돌아갑니다.

문 제출·평가

현재 동작

문 근처 E → 큰 판단 입력창 → 최종제출 → 확인/취소 → 대기 → 평가 결과.

- 정상/사기 중 하나 선택. 판단근거는 한글/여러 줄/복사·붙여넣기 가능, 10,000자 한도.
- 대응행동 오른쪽 체크박스: 체크=했다, 미체크=안 했다. 시나리오별 5개 예시 항목.
- 미선택/빈 근거는 제출 금지. 확인 취소와 X/ESC 닫기는 현재 답안 유지.
- 확인한 답안의 사본을 제출. 평가 중에는 중복 제출과 X/ESC 닫기를 막음.
- 대기 중 조사 팁 순환 표시. 오류 시 다시 판단하기 또는 입력창 복귀.
- 결과: 점수/잘한 점/부족한 점/예방 팁. 다시도전하기는 방으로 돌아가 추가 조사하는 것.
- 재도전/창 닫기는 메모와 조사 및 입력 내용 유지. 새 게임 시작 때 모든 플레이 데이터 초기화.

실제 AI 연결 상태

기본은 테스트 평가입니다. 화면에 실제 AI가 아님을 표시합니다.
규칙 점수는 입력 길이와 체크 수로 동작을 확인할 뿐 정답·근거의 타당성을 평가하지 않습니다.
실제 AI 모델, API 키, 백엔드, 채점 기준은 포함하지 않았습니다.

실제 서버가 준비되면 .env.example을 .env.local로 복사하고 다음을 설정하세요.

VITE_EVALUATION_URL=/api/evaluate
VITE_DEMO_FAIL_ONCE=false

설정 후 Vite를 재실행합니다. /api/evaluate를 프런트 개발 서버가 자동으로 만들지는 않습니다.
백엔드 라우팅 또는 Vite 프록시/동일 출처 배포가 별도로 필요합니다.
VITE 변수는 브라우저에 공개되므로 API 키를 넣지 마세요. AI API 키는 백엔드에서 관리하세요.

요청 JSON

POST, Content-Type: application/json

{
  "schemaVersion": 1,
  "requestId": "요청 고유 ID",
  "scenarioId": 1,
  "verdict": "scam",
  "reason": "조사한 사실을 근거로 한 설명",
  "responseActions": [{ "id": "official", "done": true }],
  "investigation": {
    "memo": "현재 메모",
    "objects": ["smartphone", "door"],
    "questions": [],
    "computerPages": []
  }
}

verdict는 normal 또는 scam. responseActions에는 해당 시나리오의 모든 항목이 true/false로 포함됩니다.
서버는 scenarioId로 자기 쪽의 확정 시나리오/정답/평가 기준을 조회해야 합니다.
클라이언트에 들어온 조사 여부만으로 실제 조사나 정답을 신뢰하지 마세요.
같은 requestId의 재시도는 서버에서 중복 처리하지 않도록 구현하는 것을 권장합니다.

응답 JSON

{
  "score": 85,
  "strengths": ["잘한 점"],
  "improvements": ["보완할 근거"],
  "preventionTips": ["예방 팁"]
}

score는 0~100 숫자, 나머지 세 필드는 문자열 배열이어야 합니다.
필드 누락/범위 오류/HTTP 오류/20초 시간초과는 오류 화면으로 처리합니다.
실제 외부 서버 연결은 미검증이며, 계약 형태의 가짜 서버 응답으로 어댑터를 자동 검사했습니다.

경계·오브젝트 충돌

방 밖으로 나가지 않기

기준 캔버스는 1920×1080입니다. 이동 가능 방은 config.js ROOM으로 별도 지정합니다.
기본 ROOM: 왼쪽120, 위220, 너비1680, 높이740.
플레이어 표시 크기76×100일 때 중심 이동 범위는 x158~1762, y270~910입니다.
플레이어 전체 사각형이 방과 브라우저의 게임 화면 안에 남습니다.

오브젝트와 겹치지 않기

OBJECTS의 bodyW/bodyH를 이용해 5개 오브젝트의 충돌 사각형을 만들고,
플레이어 표시 사각형 전체를 이동 경로와 함께 검사합니다.
축별 연속 경로 검사로 큰 이동량에서도 얇은 사각형을 관통하지 않으며,
한 축이 막히면 다른 축으로 벽을 따라 이동할 수 있습니다.
시작 위치가 방 밖이나 오브젝트 안이면 가능한 안전한 위치로 보정합니다.

계산은 src/game/collision.js, 실제 호출은 RoomScene.update에서 합니다.
이동 시 Phaser GameObject 위치를 갱신하고 Arcade body를 동기화합니다.
중복 이동이 생기지 않게 Arcade body.moves는 false입니다. 충돌 계산은 collision.js가 담당합니다.

실제 에셋 연결 시

- PLAYER.w/h: 표시 크기와 플레이어 충돌 크기. 투명 여백까지 막히는 것을 피하려면 에셋 여백을 최소화하세요.
- OBJECTS w/h: 표시 크기, bodyW/bodyH: 막히는 사각형 크기.
- 오브젝트 그림 전체와 겹침을 막으려면 bodyW=w, bodyH=h를 유지하세요.
- ROOM: 실제 방 이미지의 바닥 범위. 브라우저 실제 픽셀이 아닌 1920×1080 내부 좌표입니다.
- ROOM_COLLIDERS: 배경 이미지에 그려진 책상/침대 등 추가 가구의 사각형.

export const ROOM_COLLIDERS = [{ x: 450, y: 650, w: 200, h: 100 }];

현재 배경 원본이 없으므로 임의 가구 충돌을 추가하지 않았습니다.
오브젝트 주변 E키 범위(기본200px)와 충돌 사각형은 별개입니다.
큰 가구를 추가하면 접근 가능한 위치에서도 E키 범위가 충분한지 확인하세요.

ScamGuard 종합 정리 · v3

1. 프로젝트 기준

- 사기 예방을 위한 단서 조사 교육용 게임.
- React + Vite + Phaser, VSCode/Node.js/Git 환경.
- 내부 기준 해상도 1920×1080. 16:9 유지, 브라우저에 맞춰 확대/축소.
- 배경/버튼/플레이어/오브젝트는 이미지 에셋. 아직 제공되지 않아 누락 시 코드의 임시 도형/텍스트를 표시.
- 메뉴와 방은 Phaser, 조사/메모/답안창은 Phaser DOM. 컴퓨터 등 UI 에셋을 재사용하고 내용만 데이터로 변경.
- 메시지/질문/답변 높이 자동 조절, 최대 너비 줄바꿈, 긴 내용 내부 스크롤. 말풍선은 CSS로 그림.

2. 전체 게임 흐름

메인 → 시나리오 선택 → 방에서 조사 → 문에서 판단/근거/행동 제출 → 확인 → 평가 대기 → 결과.
메인에는 게임시작/게임방법/게임종료. 종료 확인 후 브라우저 탭을 강제로 닫지 않고 게임끝 화면 표시.
시나리오 4개 중 하나를 선택해야 시작 가능. 선택창의 게임 시작하기에서 매번 데이터를 초기화.
ESC 일시정지: 창닫기/메인화면으로가기. 다른 탭으로 이탈해도 일시정지.

3. 방과 조작

WASD 이동, E로 범위 내 최근접 오브젝트 하나만 상호작용. 동일 거리면 등록 순서로 하나 선택.
오브젝트: 스마트폰/전화기/메모장/컴퓨터/문. E 아이콘은 대상 하나 위에만 표시.
조사창 중에는 이동과 다른 오브젝트 조사를 잠금. E를 누르고 있어도 중복 창이 열리지 않음.
방 경계와 오브젝트 충돌은 플레이어 전체 표시 사각형을 기준으로 처리.
빠른 이동에도 경로를 검사해 관통 방지. 한 축이 막히면 다른 축으로 벽 따라 이동.
배경 가구는 그림만으로 자동 충돌하지 않으며 ROOM_COLLIDERS에 추가.
기본 방 중심 이동 범위 x158~1762, y270~910 (플레이어76×100, 방120/220/1680/740).

4. 스마트폰

메시지 목록 3개 → 상세 [뒤로가기/추가질문] → 질문 목록4개 [뒤로가기] → 질문·답변 [뒤로가기].
답변→질문목록→선택한 메시지상세→메시지목록 순으로 복귀.
모든 단계 X/ESC 전체 닫기. 재진입은 목록부터, 조사 기록은 유지.

5. 전화기

공식 연락처 [전화걸기] → 통화 중 문의4개 → 답변 [뒤로가기/통화종료].
뒤로가기=문의목록, 통화종료=공식연락처, X/ESC=전체 닫기.
게임 내부 모의 통화이며 실제 전화를 걸지 않음.

6. 메모장

다중행 입력, 한글, 드래그 선택, Ctrl+A/C/V/X, 내부 스크롤.
닫기/ESC 후 다시 열어도 내용 유지. 입력 중 게임의 키보드 캡처 중지.

7. 컴퓨터

공통 X/ESC 전체 닫기, 하위 단계 뒤로가기, 동적 텍스트/스크롤.
1 채용: 선택지4개 → 각 내용 [뒤로가기].
2 재택부업: 일반3개 → 내용 / 업무사이트1개 → 업무목록 [뒤로가기] → 업무내용 [뒤로가기].
3 투자 리딩방: 금융회사홈페이지/등록조회공시 → 내용 [뒤로가기]. 투자앱 → 투자앱항목 → 가상출금요청 결과 [뒤로가기]. 공식앱정보 → 공식앱항목 [뒤로가기].
4 숙소예약: 일반2개 → 내용. 숙소검색 → 검색결과 [뒤로가기/예약문의] → 문의 [뒤로가기]. 예약및결제안내 [결제안내확인] → 확인내용 [뒤로가기].
숙소예약 결제안내창은 지정대로 뒤로가기 없음. X/ESC로 전체 닫기 가능.
출금은 결과 내용 표시이며 실제 거래 또는 예/아니오 선택 결정 기능은 아님.

8. 문: 최종 판단

큰 창(1500×960)에서 정상/사기 중 하나 선택, 판단근거 텍스트 입력, 대응행동 끝의 네모에 체크.
체크=했다, 미체크=안 했다. 대응행동은 시나리오별 예시 데이터.
판단 미선택/빈 근거는 제출 금지. 최대10,000자.
최종제출 → 확인창 [뒤로가기(취소)/확인]. 취소해도 답안 유지.
확인 → 판단 대기창, 조사 팁 순환. 평가 중 중복제출/창닫기 잠금.
오류 → 재시도 또는 입력창 복귀. 결과 → 점수/잘한 점/부족한 점/예방 팁.
다시도전하기는 같은 인게임으로 복귀해 추가 조사. 메모/답안/조사 유지.
메인메뉴로가기 후 새 게임을 시작하면 전체 초기화.
실제 AI 미연결: 테스트 평가라는 표시와 규칙 점수로 화면 흐름만 확인.
평가 API 어댑터/JSON 계약/시간초과 처리는 준비됨. 백엔드와 실제 AI 채점은 별도 작업.

9. 데이터 유지와 초기화

runData: scenarioId, memo, investigatedObjects, requestedQuestions, computerPages, collectedClues,
answer, submission(verdict/reason/actions), lastSubmission, evaluation, playerPosition.
창 닫기/뒤로가기/일시정지/결과에서 다시도전=유지.
시나리오 선택 후 게임 시작하기/새로고침=초기화. 외부 저장/이어하기는 없음.
collectedClues는 추후 단서 수집용 필드. 현재 조사/질문/페이지 방문 기록은 구현되었지만 별도 단서 수집 시스템은 없음.

ScamGuard 종합 통합 소스 v3 (1.2.0)

지금까지 합의한 메뉴, 조사, 메모장, 일시정지, 새 게임 초기화를 통합한 버전입니다.

처음 실행

1. ZIP 압축을 풉니다.
2. VSCode에서 scamguard 폴더를 엽니다. package.json이 보이는 폴더입니다.
3. VSCode 터미널에서 순서대로 실행합니다.

npm install
npm run dev

터미널에 나온 주소를 브라우저에서 엽니다. 파일 탐색기에서 index.html을 더블클릭하는 방식이 아닙니다.

기존 Vite 프로젝트에 적용

기존 프로젝트를 먼저 백업합니다. 이 ZIP의 src/, index.html을 사용하고, 본인의 이미지를 public/assets/로 복사합니다.
기존에 제공한 InvestigationScene.js, PopupScene의 수정 코드는 중복 적용하지 않습니다. 현재는 OverlayScene.js 하나가 팝업과 조사창을 관리합니다.
별도의 React 플러그인 설정 없이 실행할 수 있게 JSX 파일에서 React를 명시적으로 가져옵니다.
기존 package.json을 유지하려면 React, ReactDOM, Phaser, Vite 의존성이 필요합니다.

npm install phaser react react-dom
npm install -D vite

에셋 연결
