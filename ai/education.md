# 사기 예방 교육 기준

게임에서 평가하는 것은 세 가지다. 무엇을 조사했는지, 어떤 결론을 냈는지, 그 상황에서 어떻게 대응하기로 했는지를 따로 본다. 정답을 맞힌 사용자가 공식 경로를 확인하지 않았을 수 있고, 판단이 틀린 사용자도 송금을 보류하는 안전한 선택을 할 수 있다.

## 공통 행동 기준

| 관찰한 기록 | 피드백에 반영할 내용 |
| --- | --- |
| 메시지·공고·후기 열람 | 어떤 요구를 보았는지 설명한다. 로고, 후기, 발신자 이름만으로 상대방의 신원을 확인했다고 평가하지 않는다. |
| 독립된 경로로 확인 | 직접 접속한 공식 사이트의 정책, 앱의 예약 내역, 공식 대표번호의 답변 중 실제 조사한 자료를 제시한다. 두 자료를 읽었다면 내용의 일치·충돌 여부를 짚는다. |
| 확인 전 송금·정보 제공을 선택 | 정오와 별도로 어떤 정보나 돈이 노출될 수 있는지 설명한다. 최종 선택만 기록됐으면 실제 피해가 발생했다고 쓰지 않는다. |
| 절차를 보류하거나 신고를 선택 | 확인이 끝날 때까지 중단한 점을 설명한다. 피해가 의심되면 대화를 보존하고 직접 찾은 은행·플랫폼의 공식 창구에 문의하도록 안내한다. |
| 확인 기록 부족 | 확인하지 않은 항목 한 가지와 확인할 경로를 제안한다. 사용자의 의도, 피해액, 열람하지 않은 답변을 추정하지 않는다. |

## 사례별 판단 기준

| 유형 | 정상 사례에서 확인할 근거 | 사기 사례에서 대조할 근거 | 위험한 선택과 대안 |
| --- | --- | --- | --- |
| 채용 (JOB) | 공식 공고에 적힌 채용 단계·제출 경로가 안내와 일치하고 담당자 또는 합격 통보를 인사팀에서 확인할 수 있다. | 별도 사이트에서 신분증·통장 사본을 요구하지만 공식 홈페이지에는 해당 접수 경로가 없다. | 급하다는 말에 서류를 전송하기 전에 회사 홈페이지에서 찾은 인사팀에 접수처를 확인한다. |
| 재택부업 (SIDE) | 실제 업무, 보수와 출금 조건이 공식 정산 정책과 일치한다. | 참여·출금에 선입금이 필요하다는 담당자 요청과 공식 정책이 충돌한다. 소액의 첫 정산만으로 다음 요구까지 신뢰하기 어렵다. | 보증금 이체를 보류하고 입금 요청과 정산 정책을 공식 고객지원에서 대조한다. |
| 투자 리딩방 (INV) | 공식 채널에서 운영 주체와 담당자 소속을 각각 확인하고 서비스 범위와 입금 경로를 대조한다. | 실제 업체를 사칭한 계정이 원금·수익을 보장하며 개인 계좌로 송금을 재촉한다. 업체가 등록돼 있어도 대화 상대의 소속은 별도 확인이 필요하다. | 대화방에서 전달한 계좌로 입금하기 전에 직접 찾은 금융회사 대표번호로 연락한다. |
| 숙소 예약 (TRAVEL) | 플랫폼 앱의 예약 내역, 숙소, 요금, 결제 상태 및 취소 조건이 안내와 일치한다. | 예약 취소를 내세워 외부 결제를 요구하지만 앱의 예약·추가 결제 내역에서 확인할 수 없다. | 외부 링크나 계좌로 결제하기 전에 예약 번호로 플랫폼 고객센터에 확인한다. |

상대가 재촉하거나 가격이 낮다는 인상만으로 사기 판정을 확정하지 않는다. 이미 검증한 정상 절차는 진행할 수 있다. 사기 사례에서는 독립된 출처와 요청이 충돌한 지점을 짚고 추가 송금·제출을 중단하도록 안내한다. 시나리오별 점수와 정답은 사례 데이터의 평가 규칙을 따른다.

## 같은 사례에서 행동이 달라질 때

채용 메시지에 “오늘까지 신분증을 보내라”는 문구가 있었다고 하자. 메시지만 읽었다면 제출을 재촉하는 요구를 접했다고 설명한다. 공식 서류 안내까지 열어 외부 접수 페이지를 운영하지 않는다는 사실을 확인했다면 두 안내가 서로 다르다는 점을 잘한 행동으로 평가한다. 사용자가 “인사팀에도 전화했다”고 적었지만 문의 기록이 없으면 추가로 확인할 근거로 남긴다.

채용·재택부업은 백엔드의 사례 데이터를 기준으로 작성했다. 투자·숙소는 사례 데이터 반영 시 대조할 교육 기준안이다. 공동 검토 항목은 유형별 공식 확인 경로, 위험 행동 이벤트, 확인 사실의 출처 매핑이다.
