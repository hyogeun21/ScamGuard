# 컴퓨터 조사 수정 안내

## 화면 연결

| 시나리오      | 연결                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| 1 채용        | 첫 화면 4개 → 각 내용 → 첫 화면                                               |
| 2 재택부업    | 일반 3개 → 내용 / 업무 사이트 → 업무 목록 → 업무 내용                         |
| 3 투자 리딩방 | 금융회사/등록조회 → 내용 / 투자앱 → 항목 → 가상출금 결과 / 공식앱 정보 → 항목 |
| 4 숙소예약    | 일반 2개 → 내용 / 검색 → 검색결과 → 예약문의 / 예약·결제 → 결제안내확인       |

컴퓨터창은 X 또는 ESC로 전체 닫습니다. 뒤로가기는 기획에 지정된 이전 화면으로 이동합니다.
숙소예약의 예약 및 결제안내창은 뒤로가기 없이 결제안내확인 버튼만 있습니다.
가상출금요청은 승인/거부 결과와 이유를 표시합니다. 현재 거부 예시이며 예/아니오 선택창이나 실제 거래 기능이 아닙니다.

## 수정 파일

`src/game/computerContent.js`의 COMPUTER_SCENARIOS를 수정합니다.
1=채용, 2=재택부업, 3=투자 리딩방, 4=숙소예약입니다.

각 시나리오는 root(시작 화면 ID)와 nodes(화면 데이터)를 가집니다.
각 화면에는 다음 데이터가 있습니다.

```js
{
  title: '화면 제목',
  body: '본문\n\n여러 줄도 가능',
  backTo: '이전화면ID', // null이면 뒤로가기 없음
  actions: [
    { label: '선택지 문구', target: '이동할화면ID' },
    // 아래 형태는 본문 목록 대신 하단 이미지 버튼으로 표시합니다.
    { label: '예약문의', target: 'inquiry', buttonKey: 'computerInquiry' }
  ]
}
```

모든 target/backTo는 같은 시나리오 nodes 안의 ID와 일치해야 합니다. npm test로 검사할 수 있습니다.
업무 개수는 tasks.actions에 추가하고 그 target에 해당하는 업무 페이지를 nodes에 추가하면 늘어납니다.
업무의 backTo는 tasks로 지정합니다.

## 콘텐츠 상태

구체적인 제목을 제공하지 않은 일반 선택지와 모든 본문은 교체용 예시입니다.
레이아웃과 화면 연결을 먼저 구현한 상태이며 실제 교육용 문구를 확정한 것은 아닙니다.
외부 웹사이트, 실제 금융조회/숙소 검색/예약/출금은 연결하지 않습니다. 모두 게임 내부 모의 화면입니다.

## 코드 구조

OverlayScene.renderComputer가 현재 페이지를 읽고 공통 UI를 만듭니다.
가변 텍스트 높이, 내부 스크롤, 포커스/키보드 잠금은 기존 조사창과 같습니다.
computerPages는 방문한 페이지 ID를 중복 없이 보관하고 새 게임 시작 시 초기화됩니다.
화면을 닫고 다시 열면 시작 화면으로 돌아갑니다.
